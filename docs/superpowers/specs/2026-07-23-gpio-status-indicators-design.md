# GPIO 状态指示器启动初始化设计

**日期：** 2026-07-23
**状态：** 已获设计批准，等待文档审阅

## 目标

应用在树莓派上启动时初始化蜂鸣器和三色状态灯的 GPIO 输出。运行期间仅点亮绿灯；蜂鸣器、红灯和黄灯保持关闭。开发环境为 WSL2 时不访问 GPIO，并保留可诊断的日志。

## GPIO 映射与初始状态

| 用途 | BCM 引脚 | 启动电平 |
| --- | ---: | --- |
| 蜂鸣器 | 14 | LOW（关闭） |
| 红灯 | 7 | LOW（关闭） |
| 黄灯 | 25 | LOW（关闭） |
| 绿灯 | 26 | HIGH（点亮） |

GPIO 使用 BCM 编号模式。该方案假定高电平点亮绿灯，与原应用的状态灯控制方式一致。

## 启动行为

`src/voc_app/gui/app.py` 保留其现有的可选 `RPi.GPIO` 导入逻辑。作为 GUI 启动流程的一部分：

1. 在树莓派环境调用 `GPIO.setmode(GPIO.BCM)`。
2. 将 GPIO14、GPIO7、GPIO25 和 GPIO26 配置为输出，初始均置为 LOW。
3. 将 GPIO26 单独置为 HIGH，以点亮绿灯。
4. 若 `RPi.GPIO` 不可导入（例如 WSL2），仅记录跳过信息；若 GPIO 初始化失败，记录警告并继续启动 GUI。

此前启动时直接将 BCM25 置高的代码会被移除。BCM25 在新硬件中是黄灯，继续沿用旧逻辑会导致错误点亮黄灯。

## 测试

为 GPIO 初始化逻辑增加模拟 GPIO 的单元测试，验证：

- 引脚映射、BCM 模式与四个输出引脚的配置；
- 四个设备先关闭，随后仅 BCM26 被置高；
- 没有 RPi.GPIO 时不会尝试访问 GPIO；
- GPIO 调用抛出异常时，GUI 启动初始化不会中断。

测试不需要树莓派硬件，并可在 WSL2 执行。
